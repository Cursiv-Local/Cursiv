## Established causes and fixes

1. `core/science_check.py:simulated_note` gated on a lexical hypothetical/invent/mock match, then subtracted supplied/calculated numbers from **every** remaining number in the draft. It removed list numbering but had no source-location type. On unchanged U113 the reconstructed chat draft produced the exact warning containing64,88,117,120. U111089bb4b broadened this from table/12-number examples to any fresh numeric value; U113 did not change this function. The fix masks locator **spans**, not globally allowed numeric values; a separate64-hour measurement still warns. Negated/literal requests for hypothetical content are no longer a positive simulation trigger. Experiment/table and genuinely new scenario-result controls remain.
2. `completion.chat` ran native source maps through model-prose polishing and checks. `response_style.drop_self_certification` removed their valid no-AI sentence; the number checker then treated source references as invented data. A current application-generated, source-checked authoritative packet now returns after the source gate, before model-only polishing, science speculation and optional model review. A model cannot set this native ownership flag. Model-generated source explanations still pass reference validation and actual unsupported citations are withheld.
3. `claim_evidence.unbacked/privacy_overclaim` inspected literal examples and negated statements as assertions. The execution-claim helper in `claims` and self-certification filter also lacked literal boundaries. They now distinguish quoted/fenced examples and negated/conditional assertions from current-answer execution/privacy claims. Positive false tool/save/search claims remain blocked. The style filter preserves literal code and examples rather than editing their contents.
4. `self_inspection.resolve` required own/source feature phrasing and did not recognize an explicit installed relative `.py` path plus a function name. Therefore the requested `claim_evidence.py/privacy_overclaim` could fall through to generic conversation/workspace/context routes. `source_analysis.collect` seeded broad pipeline files for generic source and did not consult exact file/function targets first. The new target route resolves against existing public inventory metadata, checks access, reads the requested file first, and selects the exact declaration before bounded graph expansion. Missing/ambiguous declarations produce scoped UNKNOWN/NOT FOUND, never a substituted architecture explanation. Restricted paths and explicit no-read instructions still deny access. Budget constants are unchanged; a regression proves the target works with one file, two calls and zero expansion depth.

## Diagnostic meaning and actual inference

- `selection`: the requested mode/destination at turn start, **not** proof a backend ran. Previous `automatic_local / not selected yet` was the default before an exact model was selected; it could also conceal a legacy requested provider. The event now explicitly labels its timing and reflects the supplied routing mode.
- `classification` and `routing`: the result of the deterministic own-source intent/pre-dispatch stage. Previous `ordinary_or_native / native_or_conversation / not requested` meant this stage missed the request; it did not mean permission was denied, or that later context/planner source reads never happened.
- `tools_available`: permitted capabilities only. `tools_offered` records a prepared planner/provider schema list, explicitly not execution. `tool_result` records actual result/denial; pending workspace previews emit no execution event. `inspect: true` is permission, not target-selection success.
- `source_read`: new structural event after a fresh hash-checked installed-source read. `evidence_returned` still records material supplied/returned; those are different facts.
- `response_origin`: native installed-source answers explicitly report provider/model `none` and no inference attempted. Model transport/provider attempt/result events remain the evidence that inference actually occurred.

Deterministic inspection does intentionally bypass model inference: this already existed in U113 `self_inspection.stream`, via `source_analysis.native`/`self_contracts.answer`. It does not secretly choose Ollama or claim the selected cloud model answered. The requested selection stays recorded; a native static result explicitly says no AI model was used. An unconfigured cloud model can therefore coexist with a successful **native** source lookup, without any cloud authentication or inference. Model explanations still use the selected adapter and existing authorization gates.
