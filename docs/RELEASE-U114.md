# Cursiv 3.14-U114 — Source targeting and evidence reliability

Requests for an exact public application file and function now inspect that target first, returning checked declarations, conditions, returns and real file/line references. The existing source allowlist, hash checks, permission boundaries and read budgets remain.

Source-code line numbers are classified as locations rather than hypothetical measurements. Quoted examples, negated execution claims, mathematical self-checks and user-supplied numeric scenario inputs no longer trigger unrelated verification interruptions. False tool/source assertions and unsupported resource safety/runtime conclusions remain checked. Legitimate substantive corrections are preserved.

Native source answers explicitly identify that no model inference occurred. Diagnostics separate available tools, prepared tool schemas, executed results, pending write previews and successful/denied source reads. Manual provider selection and existing privacy/offline controls remain; notebook confirmations, memory, portable workspaces and optional USB key export are preserved.

The removed Guardian scanner/service was not restored. Git history and exact causes are documented in [the audit](U113-GUARDIAN-AUDIT.md). [Manual testing instructions and limitations](U113-MANUAL-TEST-HANDOFF.md) distinguish software regressions from real model behavior. No live AI-provider request or model inference was used for this follow-up. Real provider quality, latency and independent self-correction still need owner testing.

Release verification is pending the normal exact-source hosted gates and tagged native packages. U113 remains published until U114 artifacts and owner signatures are verified. A hosted Windows workflow reuses the existing tag-only build script and mandatory main, dependency-lock, frozen-app and portable checks; it avoids rebuilding the owner's expired temporary environment.

The initial release security gate identified seven advisories in the existing PDF dependency. U114 raises its floor and hash lock to [pypdf6.21.4](https://github.com/py-pdf/pypdf/releases/tag/6.21.4), with archive hashes verified against [PyPI metadata](https://pypi.org/pypi/pypdf/6.21.4/json). Hosted CI must validate the updated lock and PDF workflows before publication; no local dependency install was performed.
