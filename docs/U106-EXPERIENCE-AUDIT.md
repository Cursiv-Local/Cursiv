# U106 researcher experience audit

2026-10-26. Source audit of the desktop application at baseline `79a1636`, before the researcher-experience implementation. The owner's supplied plan is [U106-RESEARCHER-PLAN.md](U106-RESEARCHER-PLAN.md). Existing answer-quality and regression evidence is in [U106-BASELINE.md](U106-BASELINE.md).

This document distinguishes existing behavior, the proposed first preview, and work that remains deferred. Source inspection is not a human usability study. No first-time researcher has been recruited or timed, and no improvement in human task completion is claimed here. Any automated before/after numbers must come from the separate beginner-language benchmark and its recorded outputs.

## Existing strengths to preserve

- The notebook is append-only. `core/notebook_tools.py` checks the chain, validates allowed fields, appends through `core/fieldlog.py`, reads the record back and checks it before issuing a successful receipt. Corrections link a new record to its original.
- Plain-word action confirmation cards already exist in `core/notebook_proposals.py`, `core/intent.py`, `launcher/chat_actions.py` and `launcher/chat_badges.py`. A preview can reuse the same checked native command; model prose must never execute as a command.
- Historical notebook retrieval is application-controlled in `core/field_recall.py`; calculated summaries are computed from validated records rather than model arithmetic.
- Imported documents already retain fingerprints, source paths, dates and page text. The document search, supplied-passage citations and prompt-injection warning paths already exist.
- `core/file_access.py` is the shared boundary for file operations. Explicit workspace grants, link/traversal/credential denials, confirmation and verified receipts must remain the authority.
- Offline mode, the existing local-model setup and portable data/reference helpers already work. An interface improvement does not authorize a cloud fallback or model download.
- Separate sample notebook/document data exists in `core/demo.py`. A guided example must use an explicitly labelled preview or that established isolation; sample values must not be submitted to the person's real notebook automatically.

Paths beginning `core/`, `memory/` or `chat/` below are under `cursiv_engine/`.

## Boundary findings that constrain the design

### Workspace grants are already meaningful

`core/workspace.py:33` loads a per-person workspace grant; `:52` validates and saves it with an enabled flag. `core/file_access.py:92` validates the selected directory and `:107` rejects paths outside it, protected credentials, traversal, links/junctions, alternate streams and hard links. An external portable-workspace grant from another host is refused until it is selected explicitly there.

Use these APIs for workspace file access. A profile file, project name, model interpretation or convenience shortcut cannot grant an exception. Imported files chosen explicitly by the person are a separate library workflow; making their library visible is not permission to scan unrelated folders.

### Imported documents have no project membership yet

`core/documents.py:52` returns `HOME/.cursiv/documents` (or the separate demo library). `add()` at `:101` stores ID, name, fingerprint, page count, import date and a source reference, with no project membership. `_passages()` at `:155` builds one library cache; `search()` at `:183` searches it. `chat/conversation.py:381` calls the global `library()` and `:382` calls `search(user_text)` without a project argument.

Therefore, a new project selector by itself would still let another project's passages enter the prompt. The first preview should call this an imported library available across workspaces. A future project layer must filter before search and prompt construction, key/invalidate caches by scope, and show the actual searched scope on a no-match result. Removing one project's membership must not delete a shared imported document needed elsewhere.

### Notebook labels are not a retrieval boundary

`core/fieldlog.py:359` accepts an optional project ID; `:372` validates its restricted syntax. `:419` writes that optional key only for new entries, preserving older record fingerprints. `correct()` at `:475` carries the original project's value into its linked replacement.

`core/field_recall.py:13` has no exact project argument. Its generic text filter includes the project's text at `:87`, and statistics at `:177` scan the notebook before matching sample/site text at `:196`. A word match is not project authorization. Queries, statistics, corrections, team views and exports must use one explicit project filter before a project-scoped view can be represented as complete. Never rewrite historic notebook records or their hashes to retrofit membership.

### Project notes and conversation scope are different concepts

`memory/projects.py:58` chooses relevant per-person project summaries by names/keywords; `:97` updates model-written summaries. `chat/conversation.py:271` injects matching project notes without an active-project boundary. This can help continuity but does not create, select or authorize a research project.

`memory/semantic.py:261` filters facts by person plus family; `:702` recalls those facts and saved conversation notes, not project membership. `scope=self._conv_id` in `launcher/chat_panel.py:578` and `:582` scopes pending notebook/memory interactions to a conversation. Reusing that string as a project filter would conflate unrelated permissions and state.

Until real membership exists, use “workspace folder,” “project notes,” “imported library” and “field notebook” accurately. An interface label must not promise isolation that the model-input pipeline does not enforce.

### Portable references and old data should stay in place

`core/paths.py:49` saves drive-local references as `portable://...`; `:59` resolves them safely at the current drive root. `launcher/portable.py:47` establishes portable home/app-data paths before modules cache them. Preserve those helpers and existing storage locations.

Future project metadata can be additive: optional document membership and a separate explicit selection record, with an intentional legacy/unassigned-data view. It should not automatically move or rename existing files, reclassify memory, or rewrite notebook chains. A portable drive move must preserve project identity independently of the computer's drive letter.

## Staged validation and review

1. Record a beginner-language baseline before changing routing. Use synthetic records/documents in an explicitly isolated home and app-data folder. Capture route, actual record IDs/filters, clarification, write confirmation, source evidence and latency. Include paraphrases and negative/ambiguous cases, not only the owner's sample sentences.
2. Test ordinary-observation proposals, memory confirmation and deterministic dated retrieval independently, then through `ChatPanel`/native dispatch. Model-free routing numbers are automated behavior evidence; any live-model result must use real Ollama and be labelled separately.
3. Exercise the four actions, inline first run and embedded notebook/library in real Qt with throwaway data. Inspect rendered screenshots, layout, status/focus and sample-data separation. A screenshot proves what was rendered, not that an unfamiliar person completed a task.
4. Run relevant safety, authorization, integrity, memory, document and portable regressions, then the full existing suite and mandatory USB gate. Inspect actual output; preserve failures as evidence rather than assuming a pass.
5. Present the working local preview, measured before/after results, limitations and changed-file summary to the owner. Keep all changes uncommitted until the owner has seen the preview and explicitly authorizes a commit. No push, merge, tag or release is authorized.

## Deferred work and claims

- A unified project manager with enforced document/notebook/memory boundaries is not part of the first preview merely because a workspace label is shown.
- General two-report comparison, ambiguous contextual correction, natural-language export, export-sidecar additions and broader intent coverage each need their own complete behavior and evidence.
- Field Station, unrelated editions, external profiles and excluded files are out of scope. No changes to storage encryption, safety guidance, model-provider precedence or user data are justified by this UI audit.
- The previous U106 answer-quality, verifier-caller, conflict and reference-retrieval findings remain recorded; this experience preview must not silently mark them fixed.
- First-time human usability, physical exFAT/NTFS/FAT32/removal/full-drive tests, and real Mac behavior remain unmeasured unless separately performed. The definition of done must list any incomplete workflow plainly.
