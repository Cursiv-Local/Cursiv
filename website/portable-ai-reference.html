Portable AI: kit and offline reference.

A prepared Cursiv USB or external SSD can carry the application, its Ollama runtime, selected model files and chosen notebook or workspace data. A complete, compatible kit can run from the drive without a separate host installation of Cursiv or Ollama. Copying only a notebook or installer does not create that kit.

How it works

  1. Make a driveFrom Cursiv's menu, "Make a Cursiv USB…" (Windows): the program, the local AI engine and, if you want it, a model. Your private records aren't copied unless you choose to include them.
  2. Start from the driveCursiv-managed portable data stays on the drive. Windows, drivers, antivirus or runtime components can still leave host traces; this is not traceless operation.
  3. Move between computersThe drive letter can change; paths on the drive are stored relative to it.
  4. Bring data backNotebook entries from other laptops or phones are imported with their signatures and chain checked; conflicting histories are kept side by side, never merged.

Encryption, plainly

On a computer, conversations, memories, the field notebook, photos and phone uploads are encrypted on disk. A Cursiv USB drive stays readable, by design, so it works on any computer: anyone who has the drive can read it. Use full-drive encryption (such as BitLocker To Go) if you carry sensitive records.

Temporary-file replacement and notebook recovery checks reduce partial-write risk. Sudden removal can still lose buffered writes or damage a filesystem. Close Cursiv and eject the drive safely. Recovery procedures.

What travels with a complete kit?

The Windows application goes in Cursiv/, the bundled runtime in Ollama/, model files in Models/, and managed portable data in Home/.cursiv/. Chosen authorized workspace files travel in the drive’s workspace folder. The kit builder copies selected model manifests and blobs and can obtain the Ollama runtime during preparation.

Preparation and any missing downloads require internet access. If the needed runtime or model is absent, local AI cannot be assumed to work offline. Model licenses travel separately and should be checked before sharing. Kit-building implementation.

What the host still provides

A compatible 64-bit Windows computer, sufficient RAM and disk access, and appropriate CPU/GPU drivers. A USB drive does not supply those dependencies or bypass organizational security restrictions.

Use a computer you trust. Drive-letter changes are handled, but arbitrary filesystems, abrupt removal and every hardware combination have not been validated. Mac portable kits are not supported. Hardware requirements · Compare local AI applications.

What's tested

An end-to-end USB test (make the drive, start from it, move it, bring the data back) runs on every change and must pass before any release. Each Windows release is started from a USB layout before it's published. The developer has moved data computer to drive to another computer, and from an external SSD, on real hardware. Mac drives aren't supported for this yet. Supported platforms.

Offline preparation and verification

A portable AI workspace is a collection of dependencies and data, not only an executable. Prepare it while downloads are available, choose the model files intentionally, then test a local answer and record access with Cursiv’s offline mode enabled. A model missing from the drive is an unavailable dependency, not evidence that offline inference succeeded.

Notebook verification and supported calculations do not require model generation. Website services, optional cloud providers, search and updates remain separate network features. Cursiv’s network gate controls connections from Cursiv; it does not disconnect the host operating system or other applications.
