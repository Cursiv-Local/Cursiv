### Systems the brief asked about

1. **Answer pipeline.** user → prompt (+ verification rules, + ledger instruction) → local model streams the draft *to the screen* → `run_pass` → appended `Revised after check:` *or* `Draft + notes:`. **Cursiv notices problems and appends a correction. It never replaces the draft.** On a small model, the false positives (C-002 to C-006) mean most numeric or "should I" turns end in `Draft + notes:`.
2. **Evidence system.** Known/Inferred/Assumed/Unknown is prompt text plus a regex extractor. The only check is that an Assumed line isn't quoted verbatim without a hedge word. Nothing checks that "Known" items were actually stated. Local reference data is not retrieved in normal chat (C-016).
3. **Numbers.** No arithmetic is ever checked. The "drift" check compares the number in front of the same noun, so a correct total is flagged and a wrong total is flagged the same way (C-004). Changing one variable mid-conversation: no mechanism, beyond the model re-reading history.
4. **Revision.** detect → one rewrite → re-check → append. If the rewrite fails, Cursiv says the problems and keeps the original. That's honest, but the rewrite fails for format reasons (C-005).
5. **Memory.** Save, retrieve, number conflict and safety quarantine work. Preference conflict, safe deletion and provenance meaning are weak (C-013, C-014, C-015). Persistence between sessions is a JSONL file under `.cursiv/`. **Unverified in the installed app.**
6. **Offline enforcement.** **Can't be proven today, and code shows it isn't true.** A fresh install with no keys still contacts api.github.com on every launch, 8.8.8.8:53, DuckDuckGo with your message text on trigger words, and the Ollama registry for the embedding model. The `offline on` command enforces nothing (C-009, C-010, C-011).

## Phase 3: defect register

Severity: Critical = breaks the privacy or offline promise · High = wrong or misleading output · Medium = degraded · Low = hygiene.
"Confirmed" means a probe reproduced it or the code path is unambiguous. "Unverified" means not tested yet.

### C-001: "verified" with no check at all
Severity High · Status **Confirmed (probe)**
- Reproduction: `run_pass("Who wrote Hamlet?", "Shakespeare wrote Hamlet around 1600.", ask=None)`
- Expected: not verified; origin `inferred`.
- Actual: `clear=True, learn_origin="verified"`. Same for `"Charles Dickens wrote Hamlet in 1850."` with a `CLEAR` checker.
- Root cause: `parse_verdict("")` returns clear (`verify.py:265-267`); the no-problem branch returns `verified` (`verify.py:421-424`).
- Fix: an empty verdict means "not checked", never `verified`.
- Acceptance test: no checker, or empty reply → `learn_origin == "inferred"` and a "not checked" state.

### C-002: anything but the exact word CLEAR counts as a problem
Severity High · Status **Confirmed (probe)**
- Repro: checker replies `No problems found.`, `None.`, `**CLEAR**` or `Clear - no problems found.`
- Actual: each is listed as a problem → a rewrite → `Draft + notes: - No problems found.` shown to the user.
- Root cause: `verify.py:268` uses `fullmatch` on `clear[.!]?`.
- Fix: normalize markdown and punctuation; accept a small set of no-problem phrasings; treat replies with no concrete problem as clear.
- Acceptance: those 4 replies → clear; `"The total is wrong: 30 should be 36"` → problem.

### C-003: the "Answered by" footer forces the pass on every local reply
Severity High · Status **Confirmed (probe + code)**
- Repro: `should_verify("hey how are you", "I'm good!\n\n*[Answered by Ollama · qwen2.5:3b]*")` → `True`. Without the footer → `False`.
- Root cause: `_chat_stream` appends the footer to `reply` (`chat_app.py:3466-3469`); `should_verify` fires on any digit (`verify.py:129`).
- Effect: casual chat isn't fast, and with C-002 it ends in `Draft + notes`. With C-008 it also sends every casual message to Groq.
- Fix: check the model text only (exclude Cursiv's own notes and the `_PHASE_AFTER` text).
- Acceptance: casual turn through the real `chat()` makes zero checker calls.

### C-004: number "drift" flags correct math and can't detect wrong math
Severity High · Status **Confirmed (probe)**
- Repro: Q "4 people … 3 liters of water per day … 3 days", draft "= 36 liters total" → `changed liters from 3 to 36`. With "= 30 liters" → the same message. "17 times 23 is 381" → no arithmetic problem found.
- Root cause: `constraint_problems` treats any new number before a known noun as a changed input (`verify.py:161-178`). There is no calculator.
- Fix: only flag restated *inputs* that changed. Add a deterministic arithmetic check for expressions shown in the draft (`a × b = c`).
- Acceptance: 36 → clean; 30 → "4×3×3 is 36, not 30"; 381 → flagged.

### C-005: rewrites with numbered lists always fail
Severity Medium · Status **Confirmed (probe)**
- Actual: `revision introduced new numbers: 1, 2` → the original draft is kept.
- Root cause: `introduced_number_problems` counts list markers, ordinals and years (`verify.py:243-252`).
- Fix: ignore list markers (`^\s*\d+[.)]`) and numbers inside the ledger.
- Acceptance: the P7 probe yields `Revised after check:`.

### C-006: trivial number questions demand a ledger
Severity Medium · Status **Confirmed (probe)**
- Repro: `needs_ledger("What is 2 plus 2?")` → `True` ("2 plus" looks like a number + noun). No ledger → `Draft + notes: missing assumption ledger`.
- Fix: require the ledger for decisions, high-stakes or long questions, not for any number + word.
- Acceptance: simple-truth test A needs no ledger.

### C-007: corrections are appended; the bad draft stays
Severity High · Status **Confirmed (code; by design in HANDOFF)**
- The draft streams to the screen first; the revision goes under it. Chat history saves both.
- Decision needed (not a bug fix): keep streaming, but collapse or strike the superseded draft in the UI and store only the final text in history.
- Acceptance: after a revision, history and the next turn's context hold only the revised answer.

### C-008: the verifier sends your message and the draft to Groq/Gemini first
Severity **Critical** · Status **Confirmed (code)**
- `_router_llm` tries Groq, then Gemini, then local (`chat_app.py:3483-3494`), even when the local model wrote the answer. With a free key saved, every checked turn (every turn, given C-003) leaves the machine.
- Contradicts the constitutional Ollama-first rule.
- Fix: the check uses the local model when it answered locally; cloud only by explicit opt-in.
- Acceptance: with Groq and Gemini keys saved and Ollama running, a numeric turn makes zero requests to api.groq.com or googleapis.com.

### C-009: automatic web search sends message text to DuckDuckGo
Severity **Critical** · Status **Confirmed (code)**
- `_needs_search` triggers on substrings: `"live "`, `"current "`, `"today "`, `"recent "`, `"latest "`, `"news "` and more (`chat_app.py:266-279`). The query goes out at `chat_app.py:2881-2882` when `_is_online()`.
- "…the farm where we live and…" or "our current water supply" sends that text out. There is no setting to disable it.
- Fix: web search only on explicit `search:` or an opt-in setting; off by default.
- Acceptance: the rural prompt (Test I) produces no DNS or TCP to duckduckgo.com.

### C-010: `offline on` says "all external APIs blocked" and blocks nothing
Severity **Critical** · Status **Confirmed (code)**
- Sets `cfg["offline_mode"]` and `trust_tier=1` (`launcher/chat_commands.py:775-780`); nothing in `chat_panel.py` or `chat_app.py` reads either. Default tier is 3, "FULL COUNCIL".
- Fix: one real network gate (a module every outbound call goes through) that `offline on` controls, and that's on by default for the family build.
- Acceptance: with offline on, saved keys and a trigger word, zero external connections.

### C-011: a fresh install contacts the internet with no opt-in
Severity High · Status **Confirmed (code)**; actual traffic **Unverified (live)**
- api.github.com update check 10 s after every launch (`launcher/cursiv_launcher.py:1259`).
- TCP 8.8.8.8:53 reachability probe (`chat_app.py:2736-2745`) on the cloud path and the web-search path.
- Ollama registry pull of `nomic-embed-text` when it's missing (`semantic.py:136-137`), without asking.
- Not counted: phone sync (no-op until linked) and fleet heartbeat (needs `secrets.bat`).
- Fix: update check as opt-in or manual; no probes when offline mode is on; ask before model downloads.

### C-012: installer and marketing text overclaim
Severity Medium · Status **Confirmed (code)**
- `cursiv_setup.iss:34`: "Your data never leaves your machine" and "cascade routing (xAI → OpenAI → Claude → Ollama)". The first is false (C-008, C-009, C-011); the second contradicts local-first. The U59 header still describes U58.

### C-013: conflicting preferences aren't detected
Severity High · Status **Confirmed (probe)**
- Repro: `remember I prefer tea in the morning`, then `remember I prefer coffee in the morning`. Both are saved and both go to the model with no conflict note.
- Root cause: `conflict_reason` only catches negation or different numbers (`semantic.py:249-262`).
- Fix: same subject + "prefer/like/want" with different objects → conflict. Use embeddings when available. Newer `user_said` supersedes with the date shown.
- Acceptance: tea/coffee → conflict note, or the older one marked superseded.

### C-014: `forget <words>` deletes too much, including family memories
Severity High · Status **Confirmed (probe)**
- Repro: `forget in` deleted 3 facts, including the family fact "Water filter is in the barn".
- Root cause: substring match across `person` and `SHARED`, with no confirmation (`semantic.py:312-324`).
- Fix: word-boundary match, show matches and confirm when more than one; family facts need an explicit `forget family …`.
- Acceptance: `forget in` → "That matches 3 memories, which one?"

### C-015: "verified" memories aren't verified facts
Severity Medium · Status **Confirmed (code)**

- Fix: learned facts are always `inferred`; only `user_said` comes from the person.

- Checker on every turn, including "hey, how are you" (C-003); 3+ calls per turn on llama.

**Conclusion.** A bigger local model gives better *advice* (E, F, H, G) and much worse *honesty about sources* (B2, H). The verification pass doesn't catch real errors with either model: with a small model it rubber-stamps, with a bigger model it rejects almost everything. So the fix is in the pipeline, not in the model choice. Deterministic checks (arithmetic, "Known must quote the user", input drift, contradiction between the user's own statements), real retrieval from `reference_data`, a hard rule that sources can only be cited if retrieved, and the network gate.
